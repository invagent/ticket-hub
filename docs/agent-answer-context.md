# Agent 答复上下文

2026-09-12：自动答复/人工重答与 AI 客服查询接口统一采用分区上下文。

## 请求

`POST /open-api/replay` 外层仍为 `question`、`skill`、`use_latest_knowledge`。
`question` 包含产品名称、产品编码、模块、标题、正文，以及有来源的补充信息。
产品名称通过 `product_lines` 查询，不把内部编码当作可读名称。没有标题时省略标题段。
正文 HTML 转为文字，图片链接单独提取，不把图片 URL 当作已识别内容。

自动答复直接读取关联工单的当前正文及附件 `extracted_text`，不依赖 Hub 创建时的
正文快照。主问题保持 Hub 内容，关联工单补充内容标明来源，子任务专属图片不混用。

图片包括附件、HTML img、图片超链接、Markdown 图片及带图片扩展名的裸链接。
复用已提取结果；缺失时在 replay 之前同步识别。正文链接注册为附件以缓存识别结果。
MinIO 图片通过配置的存储客户端读回；外链传给视觉模型，不在应用服务器下载任意链接。
成功结果放入 `【补充信息—图片提取】`，包含文字/关键字段、页面位置、摘要和识别限制。
无法识别、未配置或超限会明确标记，绝不推测图片内容。

## 配置

- `VISION_ENABLED=true`
- `VISION_MODEL=qwen-vl-max`
- `VISION_API_KEY`：仅在服务器受限权限环境文件设置，不提交仓库。
- `VISION_BASE_URL`：可配置业务空间的 OpenAI 兼容地址；为空保持原 DashScope 地址。
- `VISION_MAX_IMAGES_PER_TICKET`：本次图片处理上限，默认 5。
- `ATTACHMENT_MAX_BYTES`：从 MinIO 读回待识别图片的大小限制，默认 10 MiB。

图片识别服务与自动答复开关独立；本改动不启用原先关闭的自动回复或外部回写。
没有有效视觉密钥时，已有 OCR 仍可复用，缺失图片明确标注未识别。
免费额度及“用完即停”应在供应商控制台核对，调用成功不代表一定免费。

## 验证

单元回归覆盖：编码映射、标题缺失、图片单独输入、HTML/Markdown 链接去重、
Hub 快照之后到达的 OCR、识别缓存、MinIO 图片、图片失败/限额、子任务隔离、
实际 replay 传参、对外查询和自定义视觉服务地址。
不进行自动发送客户回复的验证；环境验收使用事务回滚或纯生成调用。
